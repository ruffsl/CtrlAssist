# The seat user is given a Steam Controller's raw node

The daemon reads a Steam Controller (2026) through the raw node of the client HID device the kernel's `hid-steam` makes beside the controller's own, which a stock machine gives to root alone. The rule the packages ship, `70-ctrlassist.rules`, gives that node to the user in front of the seat, by the `uaccess` tag, for the controller's four product numbers (`28de:1302` on a cable, `1304` in a Puck, `1305` in a Steam Machine's receiver, all on USB, and `1303` over Bluetooth) and only for the client device, which the driver puts in a group of its own, `0103`. The node is not limited to what CtrlAssist does with it: any program of the user's can read everything the controller reports and send it any output or feature report, its settings and its lizard mode among them, and opening it takes the controller's joystick away from every other program.

**Risk.** Low. It reaches one kind of device the user has plugged in, and nothing that types or points beyond what the controller itself does. Steam's own udev rules give the seat every raw node of Valve's vendor number, this one among them, wherever Steam is installed, so on most machines that have this controller the grant is already there. On a machine several people share, one user's program could keep the node open, switch away, and go on reading the next user's controller; logind takes the access away on a switch but a descriptor already open stays good, as for [uinput and uhid](uinput-uhid-grant.md). The logind behavior here is as the agent that wrote the rule knew it, not as observed.

**Mitigation.** The rule matches the client device by its driver, its group and its four product numbers, so no other raw node of Valve's, a Puck's charging-pin interface say, is given.

**Closes when.** The raw node is opened for the daemon by something the system trusts, as the hiding service opens a PlayStation pad's, and the seat is given nothing. That waits on the hiding service taking a pad that has a keyboard and a mouse beside its gamepad, which is the maintainer's to decide.
